# Техническая спецификация: Веб-игра «Шахматы» (Single-File Vanilla HTML/CSS/JS)

## 1. Архитектура проекта и структура файла
Проект должен состоять ровно из **одного файла**: `index.html`. 
Внутри файла должны быть строго разделены три блока:
1. `<!DOCTYPE html>` + мета-теги и стили в теге `<style>`.
2. Разметка интерфейса в теле `<body>`.
3. Вся игровая логика, состояние и обработчики событий в теге `<script>`.

Никаких внешних CSS-фреймворков (Tailwind, Bootstrap) и библиотек (jQuery и др.). Иконки фигур — стандартные **Unicode-символы шахмат**.

---

## 2. Модель данных и Состояние игры (State)

В объекте состояния (`gameState`) должны храниться следующие параметры:
```javascript
let gameState = {
    board: [], // Массив 8x8, содержащий объекты фигур или null
    turn: 'w', // 'w' — ход белых, 'b' — ход черных
    selectedSquare: null, // {r, c} выбранная клетка или null
    validMoves: [], // Массив возможных ходов для выбранной фигуры [{r, c}, ...]
    moveHistory: [], // История ходов в текстовом виде
    isGameOver: false,
    statusMessage: "Ход белых"
};
```

Структура объекта фигуры:
```javascript
{
    type: 'p' | 'r' | 'n' | 'b' | 'q' | 'k', // пешка, ладья, конь, слон, ферзь, король
    color: 'w' | 'b' // белый или черный
}
```

## 3. Требования к UI/UX и CSS (Адаптивность)

### 3.1. Макет (Layout)
*   **Desktop:** Центрированный контейнер. Слева/справа или сверху — панель информации (статус, чей ход, история), доска строго по центру.
*   **Mobile (Portrait):** Вертикальный колонный стек (Flexbox `flex-direction: column`).
    *   Шапка со статусом игры.
    *   Шахматная доска (квадратная, занимает всю доступную ширину с отступами `max-width: 90vw; max-height: 90vw;`).
    *   Панель управления (Кнопки «Новая игра», «Отменить ход»).

### 3.2. Стилизация доски и клеток
*   Доска реализуется через CSS Grid (`grid-template-columns: repeat(8, 1fr)`).
*   Клетки: чередование классов `.light` (например, `#f0d9b5`) и `.dark` (например, `#b58863`).
*   Подсветка:
    *   Выбранная клетка: акцентный цвет фона (например, `rgba(20, 85, 30, 0.5)`).
    *   Возможные ходы: точка внутри клетки (`::after` элемент с кружком) или подсветка фона клетки.
    *   Шах королю: красный фон клетки короля.

## 4. Игровая логика и Алгоритмы (JavaScript)

### 4.1. Инициализация доски (`initBoard()`)
Заполнить массив `board` 8х8 начальной шахматной расстановкой:
*   Ряд 0 (черные фигуры): Ладья, Конь, Слон, Ферзь, Король, Слон, Конь, Ладья.
*   Ряд 1 (черные пешки): 8 пешек.
*   Ряды 2–5: `null` (пустые клетки).
*   Ряд 6 (белые пешки): 8 пешек.
*   Ряд 7 (белые фигуры): Ладья, Конь, Слон, Ферзь, Король, Слон, Конь, Ладья.

### 4.2. Рендеринг (`render()`)
*   Очистить HTML-контейнер доски.
*   Пройти циклом по массиву `board`, создать элементы `div` для каждой клетки.
*   Привязать атрибуты `data-row` и `data-col`.
*   Вывести Unicode-символ фигуры, если клетка не `null`. Применить классы цвета (`white-piece`, `black-piece`).
*   Обновить текстовый статус игры в DOM.

### 4.3. Обработка кликов (`handleSquareClick(r, c)`)
1. Если `gameState.isGameOver`, прервать выполнение.
2. Если фигура не выбрана (`selectedSquare === null`):
   * Клик по своей фигуре (совпадает с `gameState.turn`) -> записать в `selectedSquare = {r, c}`.
   * Рассчитать массив легальных ходов для этой фигуры -> записать в `validMoves`.
3. Если фигура уже выбрана:
   * Клик по той же клетке -> сбросить выбор (`selectedSquare = null`, `validMoves = []`).
   * Клик по другой своей фигуре -> перевыбрать фигуру и пересчитать `validMoves`.
   * Клик по клетке из `validMoves` -> **Совершить ход**:
     * Переместить фигуру в массиве `board`.
     * Проверить превращение пешки (если пешка дошла до края — автоматически превращать в Ферзя для упрощения MVP).
     * Сменить очередь ходов (`turn = turn === 'w' ? 'b' : 'w'`).
     * Проверить условия Шаха / Мата / Пата.
     * Сбросить выбор (`selectedSquare = null`, `validMoves = []`).
     * Вызвать `render()`.

### 4.4. Правила перемещения фигур (Валидация ходов)
Для каждой фигуры должна быть написана функция генерации базовых ходов (`getPotentialMoves(r, c)`):
*   **Пешка (`p`):** Шаг на 1 клетку вперед (или 2 с начальной позиции), взятие по диагонали. Учитывать направление движения в зависимости от цвета (`w` идет вверх, `b` вниз).
*   **Конь (`n`):** Буква «Г» (8 возможных направлений).
*   **Слон (`b`):** Диагонали до упора или первой преграды.
*   **Ладья (`r`):** Горизонтали и вертикали до упора или первой преграды.
*   **Ферзь (`q`):** Комбинация ладьи и слона (линии + диагонали).
*   **Король (`k`):** На 1 клетку в любую сторону.

*(Примечание для агента: Проверка шаха своему королю при ходе может быть опущена для упрощения MVP, либо реализована базово. Фокус на корректности геометрии ходов фигур).*

## 5. Требования к UI-элементам управления
В нижней или верхней части экрана разместить панель с кнопками:
1. **«Новая игра»** — вызывает `initBoard()`, сбрасывает `turn = 'w'`, очищает историю.
2. **«Отменить ход»** — откатывает состояние доски на 1 шаг назад (требует сохранения копии состояния перед каждым ходом).
