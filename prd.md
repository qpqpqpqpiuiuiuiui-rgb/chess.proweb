
# PRD: Веб-игра «Шахматы» (Single-File Vanilla JS)

## 1. Введение и цели проекта
**Цель:** Создать полностью функциональную, легкую и кроссплатформенную игру в шахматы, которую можно запустить в любом современном браузере без установки дополнительных зависимостей и сборщиков. Весь код должен быть упакован в **один `.html` файл**.

**Основные ценности:**
*   **Портативность:** Один файл легко переслать, запустить локально или разместить на любом хостинге (GitHub Pages, Netlify).
*   **Простота поддержки:** Отсутствие сложных фреймворков (React, Vue) и npm-пакетов.
*   **Адаптивность:** Комфортная игра как на больших десктопных мониторах, так и на экранах смартфонов.

---

## 2. Целевая аудитория
*   Любители шахмат, желающие быстро сыграть партию с другом за одним устройством (Hotseat).
*   Пользователи мобильных устройств и ПК, ищущие легкую веб-игру без регистрации и рекламы.

---

## 3. Технический стек
*   **HTML5:** Разметка структуры (доска, панели информации, кнопки управления).
*   **CSS3 (Flexbox / Grid, Media Queries):** Стилизация доски, фигур (Unicode-символы или SVG), адаптивная верстка под разную ориентацию экрана.
*   **JavaScript (ES6+):** Управление состоянием игры, валидация ходов, шахматная логика, обработка пользовательского ввода (клик/тач).

---

## 4. Функциональные требования (Features)

### 4.1. Игровой процесс (Core Gameplay)
*   **Режим игры:** Локальный мультиплеер («Игрок против Игрока» на одном экране / Hotseat).
*   **Очередность хода:** Белые ходят первыми, затем черные. Индикация текущего хода.
*   **Система ввода:** 
    *   Клик по фигуре -> подсветка возможных ходов -> клик по целевой клетке (оптимально для мобильных устройств).
    *   *(Опционально)* Drag-and-drop для десктопов.
*   **Правила шахмат (MVP+):**
    *   Корректное перемещение всех фигур (Пешка, Конь, Слон, Ладья, Ферзь, Король).
    *   Превращение пешки (Promotion) при достижении последней горизонтали (выбор фигуры: Ферзь, Ладья, Слон, Конь).
    *   Определение состояний **Шах (Check)**, **Мат (Checkmate)** и **Пат (Stalemate)** с завершением игры.
    *   *(Опционально для MVP)* Рокировка и взятие на проходе (En passant), если позволяет объем кода, иначе вынести в будущие итерации.

### 4.2. Интерфейс пользователя (UI / UX)
*   **Шахматная доска:** Классическая сетка 8х8 с чередованием светлых и темных клеток. Буквенная (A-H) и цифровая (1-8) оцифровка краев доски.
*   **Отображение фигур:** Использование стандартных шахматных Unicode-символов (`♔, ♕, ♖, ♗, ♘, ♙` и `♚, ♛, ♜, ♝, ♞, ♟`) для избежания внешних графических зависимостей.
*   **Информационная панель:**
    *   Чей ход в данный момент.
    *   Таймер партии (опционально).
    *   История ходов (текстовый лог в стандартной нотации, например, `e2-e4`).
*   **Панель управления:**
    *   Кнопка «Новая игра» (сброс позиций).
    *   Кнопка «Отменить ход» (Undo).
    *   Мобильное всплывающее окно (модалка) при объявлении мата/пата с предложением начать заново.

---

## 5. Требования к адаптивности (Responsive Design)

Игра должна корректно отображаться на трех основных категориях устройств:
1.  **Desktop (ПК и ноутбуки):** Доска размещается по центру экрана, слева или справа располагаются панели управления и лог ходов. Управление мышкой.
2.  **Tablet (Планшеты):** Доска занимает большую часть экрана, элементы управления компактно размещены сверху или снизу.
3.  **Mobile (Смартфоны, портретная ориентация):** 
    *   Доска масштабируется по ширине экрана (`max-width: 100vw`, с сохранением пропорций 1:1).
    *   Размер клеток и фигур достаточен для нажатия пальцем (минимум 35-40px на клетку).
    *   Интерфейс перестраивается в вертикальный стек (доска посередине, статус сверху, кнопки снизу).

---

## 6. Архитектура единого файла (`index.html`)

Структура файла должна быть чистой и разделенной на логические секции:
```html
<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Адаптивные шахматы</title>
    <style>
        /* CSS: Сброс стилей, стили доски, фигур, адаптивность через Media Queries */
    </style>
</head>
<body>
    <div class="game-container">
        <!-- HTML: Интерфейс, статус, доска, кнопки -->
    </div>

    <script>
        /* JS: Игровая логика, состояние, валидация, рендеринг */
    </script>
</body>
</html>
```

---

## 7. Нефункциональные требования
*   **Производительность:** Отсутствие лагов при кликах и пересчете возможных ходов (мгновенный отклик UI).
*   **Совместимость:** Поддержка всех актуальных браузеров (Chrome, Safari, Firefox, Edge на ПК и мобильных ОС).
*   **Автономность:** Полное отсутствие внешних запросов к сети (все стили, скрипты и шрифты/символы внутри файла).

---

## 8. Этапы разработки (Roadmap)

*   **Фаза 1 (MVP - Базовый каркас):**
    *   Верстка HTML и CSS-сетки доски 8х8.
    *   Отрисовка фигур по начальной расстановке.
    *   Реализация простого клика по клеткам без проверки правил (свободное перемещение для проверки верстки).
*   **Фаза 2 (Логика и правила):**
    *   Интеграция шахматной логики (можно написать компактный движок валидации ходов на JS или использовать легковесную мини-библиотеку, внедренную в тег `<script>`, например, урезанный аналог логики валидации).
    *   Подсветка доступных ходов для выбранной фигуры.
*   **Фаза 3 (Интерфейс и адаптив):**
    *   Добавление информационной панели, индикации шаха и мата.
    *   Тонкая настройка CSS Media Queries под мобильные экраны.
*   **Фаза 4 (Тестирование):**
    *   Проверка на баги мобильных тач-событий, тестирование сценариев мата и пата.
